Захватывайте аудио на одной машине и воспроизводите его на другой — в реальном времени по сети. EchoWarp использует WebRTC для транспорта и Opus для сжатия, обеспечивая передачу аудио с низкой задержкой и сквозным шифрованием.

## Возможности

- **Потоковая передача 1:1** — сервер захватывает, клиент воспроизводит (или наоборот)
- **Дуплексный режим** — двунаправленное аудио, обе стороны слышат друг друга
- **Широковещание (1:N)** — один сервер передаёт аудио нескольким клиентам
- **Конференция (N:N)** — микширование для нескольких участников с персональными миксами (общий минус собственный)
- **Виртуальный микрофон** — полученное аудио отображается как вход микрофона (Discord, Zoom, OBS)
- **Обнаружение в локальной сети** — автоматическое обнаружение серверов через mDNS
- **Запись** — запись в WAV: общий микс, отдельные дорожки или оба варианта
- **SIMD-ускорение** — AVX/SSE (x86) и NEON (ARM) для микширования аудио
- **Сквозное шифрование** — AES + DTLS/SRTP
- **Кроссплатформенность** — macOS, Linux, Windows

## Быстрый старт

1. Скачайте готовый бинарный файл со страницы [Releases](https://github.com/lHumaNl/EchoWarp/releases) (без зависимостей — opus слинкован статически)
2. Запустите `EchoWarp server` или `EchoWarp client`
3. Настройте всё в интерактивном TUI и нажмите Enter для старта

> **Пользователям Windows:** В архиве релиза есть файлы `EchoWarp Server.bat` и `EchoWarp Client.bat` — просто дважды кликните нужный. Открывать cmd.exe вручную не нужно.

## Интерактивный TUI

TUI является основным интерфейсом EchoWarp. Просто запустите `EchoWarp server` или `EchoWarp client` — экран интерактивной настройки откроется автоматически.

### Экран настройки

Экран настройки имеет двухколоночный макет:

**Левая колонка — Аудиоустройства.** Отображает все доступные устройства ввода/вывода с их параметрами (каналы, частота дискретизации, разрядность). В дуплексном режиме или режиме конференции вы назначаете отдельные роли захвата `[C]` и воспроизведения `[P]`. Создание виртуального устройства доступно прямо из списка.

**Правая колонка — Настройки.** Здесь настраиваются все параметры сессии со встроенной валидацией:

| Настройка | Описание |
|-----------|----------|
| Адрес сервера | IP/имя хоста сервера (только для клиента) |
| Порт | TCP-порт (по умолчанию: 4415) |
| Пароль | Пароль аутентификации |
| Режим | Normal / Reverse / Duplex |
| Макс. клиентов | Максимальное число подключений (только для сервера) |
| Частота дискретизации | 8000 / 16000 / 24000 / 48000 Гц |
| Каналы | Моно / Стерео |
| Битрейт Opus | 16–512 кбит/с |
| Эхоподавление | AEC для дуплексного режима |
| TLS | Включить/выключить с указанием путей к сертификату и ключу |
| Уровень логирования | debug / info / warn / error |

Переключайтесь между колонками с помощью `Tab`, перемещайтесь по полям стрелками и нажмите `Enter` для подтверждения и запуска потоковой передачи.

### Обнаружение в локальной сети

На экране настройки клиента нажмите `Ctrl+F` для открытия оверлея обнаружения. EchoWarp использует mDNS для автоматического поиска серверов в локальной сети — выберите один из списка, и поля адреса/порта заполнятся автоматически.

### Профили устройств

Нажмите `Ctrl+O` для открытия оверлея профилей. Сохраните текущую конфигурацию устройств как именованный профиль, загрузите ранее сохранённый или удалите ненужные профили. Профили запоминают назначения и роли устройств.

### Экран потоковой передачи

После подключения TUI отображает статус потоковой передачи в реальном времени:

- **Статистика соединения** — RTT, джиттер, потери пакетов с индикаторами близости к пороговым значениям качества
- **Качество соединения** — общий индикатор (Отлично / Хорошо / Удовлетворительно / Плохо), рассчитанный на основе RTT, джиттера и потерь
- **Анализатор спектра** — визуализация частотного спектра FFT аудиосигнала в реальном времени
- **VU-метры** — индикаторы уровня аудио по каналам
- **Битрейт** — отображение текущего битрейта загрузки/скачивания
- **Управление устройствами** — регулировка громкости, отключение звука, переключение устройств
- **Панель логов** — переключаемый прокручиваемый просмотр логов

## Режимы потоковой передачи

EchoWarp имеет четыре режима потоковой передачи. Выберите тот, который подходит для вашего сценария — режим выбирается на экране настройки TUI (на стороне сервера) или определяется автоматически (на стороне клиента).

### Normal — односторонний: от сервера к клиентам

Сервер захватывает аудио и отправляет его всем подключённым клиентам. Клиенты только слушают.

```
Server [захват аудио] ───→ Client 1 [воспроизведение]
                      ├──→ Client 2 [воспроизведение]
                      └──→ Client N [воспроизведение]
```

**Когда использовать:** передача музыки/подкастов слушателям, трансляция системного звука (YouTube, Spotify) в другую комнату, отправка loopback-потока на удалённую машину.

**Необходимые устройства:**

| Сторона | Захват (вход) | Воспроизведение (выход) |
|---------|:-:|:-:|
| Сервер | требуется | — |
| Клиент | — | требуется |

**Участники:** 1 сервер + 1…N клиентов (задаётся в настройке *Макс. клиентов* в TUI).

---

### Reverse — односторонний: от клиентов к серверу

Противоположность Normal. Клиенты захватывают аудио и отправляют его на сервер. Сервер только слушает.

```
Client 1 [захват аудио] ───→ Server [воспроизведение]
Client 2 [захват аудио] ──┘
```

**Когда использовать:** использование удалённого микрофона на серверной машине, сбор аудио с удалённого места, отправка микрофона клиента на колонки сервера.

**Необходимые устройства:**

| Сторона | Захват (вход) | Воспроизведение (выход) |
|---------|:-:|:-:|
| Сервер | — | требуется |
| Клиент | требуется | — |

**Участники:** 1 сервер + 1…N клиентов.

---

### Duplex — двусторонний

Обе стороны одновременно захватывают и воспроизводят. Все слышат всех.

```
Server [микрофон + колонки] ⟷ Client 1 [микрофон + колонки]
                            ⟷ Client 2 [микрофон + колонки]
```

**Когда использовать:** голосовой звонок между двумя или более машинами, интерком между комнатами, совместная аудиосессия.

**Необходимые устройства:**

| Сторона | Захват (вход) | Воспроизведение (выход) |
|---------|:-:|:-:|
| Сервер | требуется | требуется |
| Клиент | требуется | требуется |

**Участники:** 1 сервер + 1…N клиентов. Поддерживает AEC (эхоподавление) для предотвращения обратной связи.

---

### Conference — микширование нескольких участников (N:N)

Сервер выступает в роли микширующего хаба. Каждый участник (сервер + клиенты) отправляет своё аудио и получает персональный микс **всех остальных** (общий минус собственный). Это предотвращает прослушивание собственного голоса.

```
Client 1 ──┐              ┌──→ Client 1 (слышит Server + 2 + 3)
Client 2 ──┤  Server hub  ├──→ Client 2 (слышит Server + 1 + 3)
Client 3 ──┘              └──→ Client 3 (слышит Server + 1 + 2)
```

**Когда использовать:** групповые звонки с 3+ машинами, удалённые репетиции, конференции с несколькими участниками.

**Необходимые устройства:**

| Сторона | Захват (вход) | Воспроизведение (выход) |
|---------|:-:|:-:|
| Сервер (только хаб) | — | — |
| Сервер (участник) | требуется | требуется |
| Клиент | требуется | требуется |

Сервер может работать как **только хаб** (без локального аудио — только микширование для клиентов) или как полноценный участник с собственным микрофоном и колонками.

**Участники:** 1 сервер + 2…N клиентов. Поддерживает запись (общий микс, отдельные дорожки или оба варианта), кик/бан и управление громкостью для каждого участника.

---

### Сводная таблица режимов

| | Normal | Reverse | Duplex | Conference |
|---|---|---|---|---|
| **Направление** | Сервер → Клиенты | Клиенты → Сервер | В обе стороны | Все ⟷ Все |
| **Устройства сервера** | Только захват | Только воспроизведение | Оба | Оба (или ничего, если хаб) |
| **Устройства клиента** | Только воспроизведение | Только захват | Оба | Оба |
| **Макс. участников** | 1 + N | 1 + N | 1 + N | 1 + N |
| **Поддержка AEC** | — | — | да | да |
| **Персональный микс** | — | — | — | да |
| **Запись** | — | — | — | да |
| **Флаг CLI** | *(по умолчанию)* | `-r` | `-X` | `--conference` |

> **Совет:** Количество клиентов задаётся настройкой *Макс. клиентов* в TUI (по умолчанию: 1). Увеличьте значение, если нужна широковещательная передача или многопользовательские сценарии.

## Руководство по маршрутизации звука

### Сценарии использования

EchoWarp поддерживает несколько сценариев маршрутизации звука. В таблице ниже показано, какой режим и какие устройства использовать в каждом случае:

| Сценарий | Режим | Устройства сервера | Устройства клиента |
|----------|-------|--------------------|--------------------|
| Передать микрофон на удалённые колонки | Normal | Микрофон `[Input]` | Колонки `[Output]` |
| Передать системный звук (YouTube, Spotify) | Normal | 🔄 Loopback `[Input]` | Колонки `[Output]` |
| Использовать удалённый микрофон в Discord/Zoom | Reverse | Колонки `[Output]` | Микрофон `[Input]` |
| Двусторонний голосовой чат | Duplex | Микрофон + Колонки | Микрофон + Колонки |
| Групповой звонок (3+ машины) | Conference | — (хаб) | Микрофон + Колонки |
| Удалённый звук как виртуальный микрофон в OBS | Normal | 🔄 Loopback `[Input]` | ⟡ Виртуальный микрофон `[Output]` |
| Поток + локальный микрофон как один виртуальный микрофон | Normal | Микрофон `[Input]` | ⟡ Виртуальный `[Output]` + 🎤 Микс микрофона |

### Loopback — захват системного звука

Loopback-устройства захватывают весь звук, воспроизводимый на машине (музыку, видеозвонки, звук игр), и делают его доступным как источник ввода.

| Платформа | Как работает | Настройка |
|-----------|-------------|-----------|
| **macOS** | Aggregate Device (колонки + BlackHole) | Установите [BlackHole](https://github.com/ExistentialAudio/BlackHole): `brew install blackhole-2ch`. Loopback-устройства появятся в TUI автоматически |
| **Windows** | Нативный loopback WASAPI | Встроен, дополнительное ПО не требуется |
| **Linux** | Monitor-источники PulseAudio | Встроен в PulseAudio/PipeWire |

В TUI loopback-устройства отмечены значком 🔄 и отображаются в разделе Input.

### Виртуальный микрофон — передача звука другим приложениям

Виртуальный микрофон делает полученный звук доступным как вход микрофона, который могут использовать Discord, Zoom, OBS и другие приложения.

| Платформа | Драйвер | Установка |
|-----------|---------|-----------|
| **macOS** | [BlackHole](https://github.com/ExistentialAudio/BlackHole) | `brew install blackhole-2ch` |
| **Windows** | [VB-Audio Virtual Cable](https://vb-audio.com/Cable/) | Скачать с vb-audio.com |
| **Linux** | PulseAudio null-sink | Создаётся из TUI: Настройки → Виртуальный микрофон → Создать |

На macOS и Windows установите драйвер и выберите его в разделе Output в TUI. На Linux TUI создаёт виртуальный sink автоматически — в других приложениях выберите **«Monitor of EchoWarp»** в качестве микрофона.

Виртуальные устройства отмечены значком ⟡ в TUI и отображают **adaptive** вместо фиксированной частоты дискретизации.

### Микширование локального микрофона в виртуальный выход

Когда вы направляете удалённый поток на виртуальное устройство вывода (BlackHole, VB-Cable), сторонние приложения — Discord, Zoom — слышат только поток, но не ваш локальный микрофон. Если вам нужно, чтобы и ваш голос, **и** поток отображались как один вход микрофона, EchoWarp может микшировать их вместе.

**Как использовать:** В TUI выберите виртуальное устройство в разделе Output. Под ним появятся устройства ввода в виде подэлементов — отметьте микрофон, который хотите подмешать:

```
🔊 Output
  ⟡ BlackHole 2ch                           stereo 32-bit adaptive   [✓]
      └─ 🎤 Built-in Microphone                                      [✓]
```

Микшированный звук (поток + микрофон) записывается в виртуальный выход. В Discord/Zoom/OBS выберите это виртуальное устройство в качестве микрофона — будет слышен и поток, и ваш голос.

**Альтернативы на уровне ОС** (без использования встроенного микшера):

| Платформа | Способ | Подробности |
|-----------|--------|-------------|
| **macOS** | Aggregate Device | Откройте «Настройку Audio-MIDI» → создайте агрегатное устройство, объединяющее ваш микрофон + BlackHole. Выберите агрегатное устройство как вход в приложении |
| **Windows** | [VoiceMeeter](https://vb-audio.com/Voicemeeter/) | Бесплатный виртуальный микшер — направьте VB-Cable и ваш микрофон в VoiceMeeter, используйте его выход как микрофон в приложении |
| **Linux** | PulseAudio combine-source | `pactl load-module module-combine-source source_name=combined slaves=<mic>,<virtual>.monitor` |

Встроенный микшер работает на всех платформах и не требует дополнительной настройки.

### Разделы устройств

TUI отображает только те разделы, которые актуальны для текущего режима:

| Режим + Сторона | Отображаемые разделы |
|-----------------|---------------------|
| Normal сервер / Reverse клиент | Только 🎤 Input |
| Normal клиент / Reverse сервер | Только 🔊 Output |
| Duplex / Conference | 🎤 Input + 🔊 Output |

### Диагностика

Выполните `EchoWarp doctor` для проверки настроек звука:

```
Audio
[OK] Audio system: 2 input device(s), 2 output device(s)
[OK] Virtual audio: BlackHole 2ch detected
```

Если виртуальный аудиодрайвер не найден, doctor покажет инструкции по установке для вашей платформы.

### FAQ

**Я хочу слушать музыку со своего компьютера на колонках в другой комнате.**
→ Запустите `EchoWarp server` на компьютере с музыкой, выберите 🔄 loopback-устройство (ваши колонки) в разделе Input. Запустите `EchoWarp client` на удалённой машине, выберите колонки в разделе Output.

**Я хочу использовать удалённый микрофон для Zoom/Discord.**
→ Запустите `EchoWarp server` в режиме Reverse на удалённой машине (той, где есть микрофон). Запустите `EchoWarp client` на своей машине, выберите виртуальное аудиоустройство (BlackHole/VB-Cable) в разделе Output. В Zoom/Discord выберите это виртуальное устройство в качестве микрофона.

**Я хочу передавать системный звук (YouTube, Spotify) на другую машину.**
→ То же, что и «музыка в другой комнате» — используйте 🔄 loopback на стороне сервера. Loopback-устройство захватывает всё, что воспроизводится через выбранные колонки.

**Я хочу, чтобы удалённый звук отображался как вход микрофона в OBS.**
→ Запустите сервер с источником звука. На своей машине (клиент) выберите виртуальное аудиоустройство в разделе Output. В OBS добавьте источник «Захват звука (входного устройства)» и выберите виртуальное устройство.

**Я хочу двусторонний голосовой чат между двумя компьютерами.**
→ Используйте режим Duplex. На обеих машинах выберите микрофон в разделе Input и колонки в разделе Output.

**Я хочу групповой звонок с 3+ машинами.**
→ Используйте режим Conference. Сервер выступает хабом (устройства не нужны). Каждый клиент выбирает микрофон и колонки. Все слышат всех, кроме собственного голоса.

**Я хочу, чтобы Discord слышал и удалённый поток, И мой голос через один виртуальный микрофон.**
→ На клиенте выберите виртуальное устройство (BlackHole/VB-Cable) в разделе Output. Под ним появится список устройств ввода — отметьте свой микрофон. EchoWarp смикширует поток и ваш микрофон в виртуальный выход. В Discord выберите виртуальное устройство в качестве микрофона.

**У меня не установлен BlackHole / VB-Cable.**
→ Выполните `EchoWarp doctor` — он точно скажет, что и как установить. На Linux дополнительное ПО не требуется.

**Loopback-устройство не появляется в TUI.**
→ macOS: сначала установите BlackHole (`brew install blackhole-2ch`). Windows/Linux: loopback-устройства встроены и должны появляться автоматически.

**Виртуальное устройство показывает «adaptive» вместо частоты дискретизации.**
→ Это нормально. Виртуальные аудиодрайверы (BlackHole, VB-Cable) адаптируются к частоте дискретизации, которую использует приложение — отображаемое значение не является значимым.

## Режим CLI

Все настройки, доступные в TUI, можно также передать через флаги CLI для сценариев и автоматизации:

```bash
# Сервер
EchoWarp server -d 1 -P mypassword

# Клиент (автоматически находит сервер в локальной сети, если -a не указан)
EchoWarp client -a 192.168.1.10 -d 2 -P mypassword

# Список аудиоустройств
EchoWarp devices
```

### Режимы

Подробное описание каждого режима см. в разделе [Режимы потоковой передачи](#режимы-потоковой-передачи).

| Режим | Флаг |
|-------|------|
| Normal | *(по умолчанию)* |
| Reverse | `-r` |
| Duplex | `-X` |
| Conference | `--conference` |

| Флаг | Краткий | Описание |

| `--device` | `-d` | Идентификатор аудиоустройства |

| `--password` | `-P` | Пароль аутентификации |

| `--config` | `-c` | Загрузить конфигурационный файл YAML |
| `--save-config` | `-s` | Сохранить текущие настройки в YAML |

### Конфигурационные файлы

Приоритет настроек: флаги CLI > переменные окружения (`ECHOWARP_*`) > файл конфигурации > значения по умолчанию.

Экран настройки TUI позволяет сохранять и загружать конфигурационные файлы интерактивно. Также можно использовать флаги CLI:

```bash
# Сохранить текущие настройки в файл
EchoWarp server -d 1 -P pass --channels 2 -s myconfig.yml

# Загрузить настройки из файла
EchoWarp server -c myconfig.yml
```

## Установка

### Готовые бинарные файлы

Скачайте со страницы [Releases](https://github.com/lHumaNl/EchoWarp/releases). Доступно для:
- **macOS** — arm64 (Apple Silicon), amd64 (Intel), включает `.app` bundle
- **Linux** — amd64, arm64, armv7, armv6
- **Windows** — amd64, arm64

### Сборка из исходного кода

Требуется Go 1.22+ и заголовочные файлы libopus для разработки.

```bash
# macOS
brew install opus pkg-config

# Ubuntu/Debian
sudo apt-get install libopus-dev pkg-config

# Fedora
sudo dnf install opus-devel pkgconfig
```

```bash
git clone https://github.com/lHumaNl/EchoWarp.git
cd EchoWarp
make build
```

Результирующий бинарный файл статически линкует opus — зависимости во время выполнения не требуются.

## Системные требования

- **macOS** 11.0+ (arm64, amd64)
- **Linux** (amd64, arm64, armv7, armv6)
- **Windows** 10+ (amd64, arm64)

Для виртуального микрофона:
- **macOS**: аудиодрайвер [BlackHole](https://github.com/ExistentialAudio/BlackHole)
- **Windows**: [VB-Audio Virtual Cable](https://vb-audio.com/Cable/)

## Сеть и межсетевой экран

### Сервер — порты, которые необходимо открыть

| Порт | Протокол | Назначение |
|------|----------|------------|
| `4415` | **TCP** | Сигнализация (аутентификация + WebRTC-рукопожатие) |
| `4415` | **UDP** | Аудиопоток (WebRTC). Мультиплексирование — один порт обслуживает всех клиентов |
| `4416` | **TCP** | Запрос информации о сессии (автоконфигурация клиента) |

> Порт `4415` используется по умолчанию и может быть изменён с помощью `--port`. Порт информации о сессии всегда равен `port + 1`.

**Кратко:** откройте **TCP 4415–4416** и **UDP 4415** для входящих соединений на сервере.

### Клиент — входящие порты не требуются

Клиент устанавливает только исходящие соединения. Никаких правил межсетевого экрана или проброса портов на стороне клиента не требуется.

### Обнаружение в локальной сети

Если вы используете автообнаружение через mDNS (`Ctrl+F` в мастере настройки), разрешите **UDP-мультикаст на порту 5353**. Эту функцию можно отключить с помощью `--no-discovery`.

### Обход NAT (STUN / TURN)

EchoWarp использует STUN-серверы для установки соединений через NAT. Если обе стороны находятся за симметричным NAT и прямое соединение невозможно, можно настроить TURN-сервер-ретранслятор (`turn_servers` в конфигурации). Как STUN, так и TURN — это **исходящие** соединения, не требующие никаких правил для входящего трафика в межсетевом экране.
